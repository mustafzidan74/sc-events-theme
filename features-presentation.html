💡 كيف تعمل معاً؟

1. قبل الفعالية: تستخدم "إدارة الأماكن" لتعريف المناطق والبوابات والسعات

2. عند الدخول: يستخدم "نظام الحضور" لتسجيل دخول الشخص

3. أثناء الفعالية: يستخدم "إدارة الحشود" لمراقبة الأعداد في كل منطقة

⏳ يحتاج تحسين

  • خريطة المعرض التفاعلية
  • أحجام البوثات (3x3, 6x6...)

❌ مطلوب للسوق السعودي

  • تكامل مع السجل التجاري
  • فوترة ZATCA للشركات
  • عقود إلكترونية
  • دفع مقسّم (عربون + باقي)
  • شهادات مشاركة للشركات

🎯 نظام البوثات المقترح

1. تعريف مخطط المعرض: رفع صورة Floor Plan وتحديد مواقع البوثات

2. أنواع البوثات: Standard (3x3m) / Premium (6x6m) / Mega (9x9m) / Custom

3. باقات العارضين: Basic (بوث فقط) / Pro (بوث + كهرباء + إنترنت) / VIP (كل شيء + إعلان)

4. نظام الحجز: اختيار الموقع على الخريطة → الدفع → تأكيد الحجز

5. إحصائيات: عدد زوار كل بوث + أوقات الذروة + تقارير للعارض

نظام الصالات المتعددة

للفعاليات التي تحتوي على عدة قاعات أو جلسات

🏛️ ما هو نظام الصالات المتعددة؟

فعالية واحدة بها عدة قاعات، والحضور يحتاج يسجل حضوره في كل قاعة يدخلها.

مثال: مؤتمر طبي فيه 5 قاعات، كل قاعة فيها محاضرات مختلفة، والحضور يختار القاعات التي يريد حضورها.

🏛️

تعريف الصالات/الجلسات

  • إضافة عدة قاعات للفعالية
  • تحديد سعة كل قاعة
  • جدول زمني لكل قاعة
  • المتحدثين في كل جلسة
  • وصف المحتوى
📱

تسجيل الحضور المتعدد

  • مسح QR عند دخول كل قاعة
  • تتبع حضور كل جلسة
  • شهادة لكل قاعة حضرها
  • شهادة شاملة للمؤتمر
  • ساعات معتمدة (CME/CPD)
📊

التقارير والإحصائيات

  • أكثر الجلسات حضوراً
  • معدل الحضور لكل متحدث
  • تحليل تنقل الحضور
  • أوقات الذروة لكل قاعة
  • تقرير شامل للمنظم

⚠️ الحالة الحالية

النظام الحالي يدعم تسجيل حضور واحد فقط للفعالية. نحتاج إضافة:

  • جدول Sessions مرتبط بالفعالية
  • جدول Session Attendance للحضور المتعدد
  • واجهة لإدارة الجلسات في Dashboard
  • تعديل صفحة المسح لاختيار الجلسة

📅 التنسيقات السعودية

  • التقويم الهجري
  • تنسيق التاريخ (dd/mm/yyyy)
  • تنسيق الوقت (12 ساعة)
  • تنسيق الأرقام (٫ العشري)
  • رموز العملة (ر.س)

📝 خطة التنفيذ

1. الملفات: إنشاء ملفات الترجمة .po/.mo باستخدام __() و _e()

2. CSS: إنشاء ملف dashboard-rtl.css مع [dir="rtl"] selectors

3. JavaScript: تعديل الـ JS للتعامل مع RTL

4. الاختبار: مراجعة كل صفحة بالعربية
